# Local photo triage

Use this skill when the user asks to sort a collection of photos for later human review. Ask for the source folder if it was not given. The default process runs entirely on the user's computer and never uploads images.

## Boundaries

- Never delete, overwrite, rename, or move source files. Do not offer automatic deletion as a follow-up.
- Scan subfolders. Ignore videos, symbolic links, and previous `_照片筛选结果_*` directories.
- Create a new timestamped result directory inside the chosen source folder on each run. Copy original file bytes and preserve their relative subfolder layout.
- Keep RAW and rendered files with the same stem in the same source subfolder together. If a format cannot be decoded locally, copy it to `无法判断` and label the reason.
- First identify the whole-image content, primary subject, background, and capture context. Then inspect the subject-specific local details and technical quality before assigning a preliminary category. Judge conspicuous problems: severe blur, subject face out of focus while the scene is sharp, extreme overall or face exposure, severe noise in smooth regions, and heavy JPEG compression. A sharp subject against a blurred background is acceptable. Use `无法判断` only when missing or conflicting evidence affects the choice, not for every weak warning.
- Inspect every sufficiently prominent detected face in group photos. A low eye-opening measurement alone cannot distinguish downward gaze, an intentional eyes-closed pose, or a blink. If nearby frames contain both low-eye and normally open-eye views but do not establish a one-frame blink, use `无法判断`; repeated adjacent low-eye frames can support an intentional pose. A normal open-mouth smile is not a defect merely because the two measured eye openings differ. A transient open-mouth/partly closed-eye combination may be labeled `有明显问题` only when the eyes themselves provide strong evidence. If a face is too small or detection is unreliable, do not infer its expression. Never claim to know whether a subtle expression is attractive or intentional.
- A highly textured background can produce a much higher sharpness number than a clear face. Do not label the face obviously out of focus from a face-to-background ratio alone; require insufficient absolute facial detail too. Recheck the same condition in the independent full-frame pass.
- Compare eye opening and hand pose with close, visually matched frames before calling a moment a blink or an unfinished action. A one-frame eye outlier with a clear neighboring expression can be an obvious problem; repeated low-eye frames support an intentional pose. Rapid or isolated hand changes without a reliable intent cue go to `无法判断` for human review.
- Flag possible subject crop, edge obstruction, moderate noise, compression, or uncertain center focus in `无法判断` for human review. A dark, uniform edge alone is insufficient evidence of an obstruction; it can be shade or intentional background. Intentional close crops, skies, vegetation, and shallow depth of field must not be rejected solely by these heuristics.
- First identify broad, overlapping content types such as people, pets, other animals, scenery, plants, food, buildings, objects, vehicles, text, art, and events. The list is open ended: label uncertain content as unknown rather than forcing a type. Identify the primary subject separately from background tags; only the primary subject selects the comparison policy. Use content tags as evidence, not as the final similarity decision.
- For similar photos, compare the actual subject and state within a capture scene. For people, distinguish front/back views and actions; for pets, compare the animal and pose; for scenery and plants, compare the view and prominent details; for food, compare the featured dish rather than the table. A shared background, photo type, or nearby filename alone does not make two photos substitutes. Recommend one technically strongest photo per group using face focus, eye state, local exposure, overall sharpness, and noise; copy other acceptable members to `相似照片待挑选`. If every member has an obvious problem, put all in `有明显问题` and identify the relative best in the CSV.
- Treat content labels as fallible. Strong local geometric overlap and close capture timing can establish that two differently labeled frames show the same physical subject, including a tighter crop. Form the strongest supported pairs first; then extend a group only when every member is compatible. File order must not decide which pair survives.
- After preliminary classification and same-action grouping, reopen every decodable source image for an independent full-frame review before ranking. The second pass uses a whole-frame fitted view rather than the first pass's centered crop, re-detects faces, checks nine local regions and a likely subject region, and reruns text recognition for text photos. Always rebuild similarity groups after this review, even when no content label changed. Recheck close capture pairs that the first pass left in different groups: a confirmed match of local subject details, short capture timing, and strong visual agreement can form a new group or replace a conflicting preliminary group. Shared setting or time alone is insufficient; keep text and visible human faces under their stricter content/action rules. Rank and copy only after the final groups are rebuilt. Use distinct evidence to challenge the original trigger: an edge warning requires a check for overlap with the primary subject, while a whole-frame exposure warning requires inspection of the subject. Keep unresolved material conflicts in `无法判断`; downgrade unsupported warnings to annotations. This verification is automatic and remains local.
- Use the subject-specific grouping, defect, ranking, and uncertainty rules in [docs/判定规范-v1.md](docs/判定规范-v1.md) when reviewing ambiguous cases or changing the processor. In particular, text/document photos require evidence that the recognized information content matches; when local text recognition is unavailable, the script only merges byte-identical preview files. Small subjects and conflicting evidence require human review. The specification is a target and its release thresholds have not yet been verified for every subject type.
- When a user reports missed similar photos, verify against the original image files if available. Screenshots of thumbnails can point to filenames but are not reliable inputs for tuning image similarity.
- If an environment cannot run the script or lacks a required image decoder, explain the limitation and keep the originals intact. Do not claim that an unsupported file was visually judged.

## Run

The reusable local processor is [scripts/triage.py](scripts/triage.py). It needs Python 3.10+ and the packages in [requirements.txt](requirements.txt), including local pose recognition, ONNX Runtime, and local text recognition. The bundled [models/model.json](models/model.json) identifies the local content model; the model files must remain alongside the script. Use a dedicated virtual environment and its Python executable for both `--plan` and `--apply`; install the requirements before sorting. On Windows, place the environment under an ASCII-only path because some MediaPipe builds cannot load bundled model files from a path with non-ASCII characters. Attempt to install [requirements-formats.txt](requirements-formats.txt) for camera RAW and HEIC/HEIF support. If a decoder is unavailable or a particular format still cannot be decoded, handle those files as `无法判断` and state that limitation in the result. If the content model cannot load, stop before sorting instead of silently omitting content recognition. All photo inference runs locally; the bundled content and text recognition models need no network during a run.

1. Run `python scripts/triage.py "SOURCE_FOLDER" --plan` to inspect counts, space needs, and potential format limitations without copying.
2. Run `python scripts/triage.py "SOURCE_FOLDER" --apply` to create the categorized copies. The user choosing a folder and asking for sorting authorizes this reversible copy step.
3. Report the result folder, category counts, and any unreadable formats or copy failures. Keep the chat response short even for hundreds of photos. Point the user to `摘要.txt` for counts and `判断标注.csv` for brief per-photo labels when wanted.

The four category folders are `推荐保留`, `相似照片待挑选`, `有明显问题`, and `无法判断`. Treat these as recommendations for the user to inspect, never as a deletion decision. The heuristic thresholds are intentionally conservative; explain that the user should review the photos before taking any later action.

The processor tags broad content with a bundled local vision model, chooses the primary comparison subject, then finds candidate scenes using time, perceptual appearance, and geometrically consistent local details. People, animals, food, scenery, text, and other subjects use different conservative merge rules and quality priorities. For people, it also compares a locally segmented subject, visible face direction, pose, and back-view silhouette when available. It builds strong same-action pairs first and merges additional photos only when each cross-group comparison agrees, so a gradual visual chain does not combine distinct actions. The second pass adds a different framing and new local measurements; it is an independent reading of the source pixels, though it uses the same bundled content model and is not a guarantee of human-level understanding. Unreliable tags, small subjects, partial faces, and artistic effects still need human review; do not describe model scores as certainty. The CSV includes brief content, primary subject, and direction tags so the user can spot mistaken interpretations without reading a long per-photo report.

Use ordinary Python commands on Windows or macOS, such as `python` or `python3`, depending on the host. Use a quoted absolute source path. The script performs a free-space check before copying; if there is not enough room, stop and tell the user rather than changing the source.
