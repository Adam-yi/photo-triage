# Photo Triage｜把选照片交给AI

假期回来，几百张照片里有连拍、不同动作，也有失焦、曝光失误和拍到一半的表情。逐张翻看费时间；只按「同一场景」去重，又可能把想保留的不同动作放进一组。

**Photo Triage** 是一个在本地运行的照片筛选 Skill。指定一个文件夹后，它会扫描照片及子文件夹，先理解整张照片的内容，再检查主体与局部细节，把结果**复制**到四类文件夹，留给你做最后选择。**它绝不删除、移动、重命名或覆盖原片。**

仓库简介：本地照片筛选 Skill：识别主体与动作，复核相似连拍和明显画质问题；只复制分类结果，保留全部原片。

## 分类效果示例

假设同一批照片有以下情况：

| 照片 | 拍摄情况 | 可能的结果 |
| --- | --- | --- |
| A、B、C | 同一人物在同一位置做近似动作，只是眼神、清晰度或拍摄距离不同 | 组成相似组，推荐其中一张，其余合格照片留给你挑选 |
| D | 仍在这个位置，但人物换了动作 | 作为另一张作品评估，不因背景相同就并入上一组 |
| E | 背景清楚，作为主体的人物明显失焦 | 有充分证据时归为「有明显问题」 |
| F | 人物低头看花，眼睛看不清 | 结合前后照片复核；意图仍不清楚时交给人工判断 |

这只是规则示意，并非对任何具体照片的结果保证。一次运行后会在源文件夹下新增：

~~~text
照片文件夹/
├── 原来的照片和子文件夹……
└── _照片筛选结果_时间戳/
    ├── 推荐保留/
    ├── 相似照片待挑选/
    ├── 有明显问题/
    ├── 无法判断/
    ├── 摘要.txt
    └── 判断标注.csv
~~~

| 分类 | 含义 |
| --- | --- |
| 推荐保留 | 没有确认的明显问题；是可信相似组的推荐照片，或暂未找到可确认替代照片。 |
| 相似照片待挑选 | 与推荐照片属于同一组，仍可能具有不同的审美或纪念价值。 |
| 有明显问题 | 多项证据支持主体失焦、严重曝光或明显抓拍失误。 |
| 无法判断 | 格式无法可靠解码，或关键的画质、动作、表情证据不足，需要亲自看。 |

这些分类是**辅助选择，不是删除决定**。程序不会生成自动删除操作。

## 安装

需要 **Python 3.10+**。仓库已包含本地视觉模型。首次安装 Python 依赖可能联网；安装完成后，照片分析在本机进行。

~~~bash
git clone https://github.com/Adam-yi/photo-triage.git
cd photo-triage
~~~

macOS：

~~~bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -r requirements-formats.txt
~~~

Windows PowerShell：

~~~powershell
py -3 -m venv C:\venvs\photo-triage
C:\venvs\photo-triage\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -r requirements-formats.txt
~~~

Windows 的虚拟环境请放在自己有写入权限且路径只含 ASCII 字符的位置；上面的路径仅作示例。部分 MediaPipe 版本无法从含中文字符的虚拟环境路径加载模型，源照片路径则可以使用中文。第二个依赖文件增加 RAW 与 HEIC/HEIF 解码支持；仍无法在本机解码的照片会保留并进入「无法判断」。

### 在 AI 助手中使用

在 Codex 中，可将整个仓库放进 ~/.codex/skills/photo-triage（Windows 通常是 %USERPROFILE%\.codex\skills\photo-triage），然后告诉它：

> 用 photo-triage 筛选 D:\假期照片。先告诉我预计扫描多少张、需要多少空间，再开始分类。

其他能够读取 SKILL.md 并执行本地 Python 脚本的助手，可按自己的 Skill 安装方式使用。**Claude、豆包桌面版、WorkBuddy 等产品的具体安装与调用兼容性尚未逐一验证**，这里不承诺即装即用。

## 开始使用

先预览扫描规模与空间需求，这一步不复制：

~~~bash
python scripts/triage.py "/path/to/photos" --plan
~~~

确认后执行分类：

~~~bash
python scripts/triage.py "/path/to/photos" --apply
~~~

把示例路径换成带引号的实际绝对路径。空间不足时程序停止复制。每次运行会新建一个结果目录，不覆盖上一轮结果。

先看四类文件夹即可；想追溯某张照片的原因，再打开 判断标注.csv。它记录相对路径、分类、简短原因、相似组、组内推荐标记和主要内容标签。摘要.txt 汇总各类数量，无需逐张阅读长报告。

## 如何判断

**第一轮：先看整体，再看局部。** 程序先识别主要内容、拍摄主体、背景与场景，再检查题材相关的细节。人物会考虑面部清晰度、眼睛与表情、动作状态；宠物关注动物主体与姿态；风景、食物、建筑、文字照片使用各自更相关的比较重点。

**相似组：寻找可以互相替代的照片。** 人物要比较主体、朝向与动作；宠物要比较姿态；风景要比较视角和主要景物；食物要比较被拍的菜品。同一背景、相邻编号或同一种题材，本身都不足以成组。景别变化、轻微低头或取景范围变化也不会自动拆组：如果主体状态与局部细节仍支持同一拍摄意图，就可以放在一起比较。

**第二轮：独立复核，再定结果。** 程序重新读取每张可解码照片，从不同的整图视角复核内容与质量，重新检查遗漏的相似组，然后才确定组内推荐照片。证据冲突时保留人工判断空间；例如低头或有意闭眼，不能只凭一个「眼睛开合」数值判为废片。更细的规则见 [判定规范](docs/判定规范-v1.md)。

## 文件与隐私

- 递归扫描照片，跳过视频、符号链接与以前生成的结果目录。
- 同一子目录里同名主干的 RAW 与 JPEG 等文件按同一张照片处理，复制到同一分类。
- 分类副本保留原有子文件夹结构；原片始终保留在原位置，原字节不变。
- 照片识别与复核均在本地运行，不把照片上传到云端；仓库不包含用户原片或分类结果。

## 适用边界

这是帮助人工筛选的工具，不是自动裁决器。它不能可靠理解所有有意的闭眼、动作过程、浅景深、特殊曝光或构图偏好；小主体、遮挡、罕见格式及不同相机风格也可能导致漏分或误分。请重点复核「有明显问题」和「无法判断」，再由你自己决定如何处理原片。

目前主要在 Windows 环境验证。macOS 提供运行步骤，但尚未完成同等范围的实测。现有回归样本来自有限的真实照片反馈，不能代表所有题材和设备。

## 仓库结构

~~~text
photo-triage/
├── SKILL.md                 # 给 AI 助手的操作边界与流程
├── CONTEXT.md               # 项目背景
├── docs/判定规范-v1.md      # 分题材的详细判定规则
├── scripts/triage.py        # 本地筛选程序
├── models/                  # 本地内容识别模型
├── tests/test_triage.py     # 回归测试
├── requirements.txt         # 核心依赖
└── requirements-formats.txt # 可选格式解码依赖
~~~

安装核心依赖后可运行 python -m unittest discover -s tests。部分真实原片回归测试需要通过 PHOTO_TRIAGE_REAL_DIR 指定照片目录；这些照片不在仓库里。

## 模型来源与许可证

随仓库提供的量化 ONNX 视觉模型来自 [Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32)，基础模型为 [OpenAI CLIP ViT-B/32](https://huggingface.co/openai/clip-vit-base-patch32)。第三方来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。本仓库自有代码和文档采用 [MIT 许可证](LICENSE)。
